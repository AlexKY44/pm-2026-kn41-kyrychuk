Звідки бралися points закритих історій: це ті самі `final_estimate` з `lr08_poker/estimates.csv` — спринт 1 закрив S-01 (1 SP) і S-03 (3 SP) = 4 SP, але S-04 зайшла в спринт і не закрилась, тому points_done=6 рахую як суму закритих; спринт 2 закрив S-04 (5 SP) і S-07 (2 SP) = 7 SP, S-06 (3 SP) зайшла і не закрилась, points_done=8.

## 2. Як рахувалася симуляція

| Поле | Значення |
| --- | --- |
| Інструмент | власний скрипт Python 3.14 |
| Прогонів | 100 000 |
| Що тягнеться випадково | velocity одного з двох моїх спринтів (random.choice([6, 8])) |
| Дата, від якої відлічуються спринти прогнозу | для сценарію «весь перший реліз» — кінець спринта 1 (2026-10-30); для сценарію залишку — кінець спринта 2 (2026-11-13) |

```python
import random
from datetime import date, timedelta

random.seed(42)
N = 100_000
velocity = [6, 8]  # points_done з velocity.csv

def simulate(remaining, n=N):
    results = []
    for _ in range(n):
        sprints = 0
        pts = remaining
        while pts > 0:
            v = random.choice(velocity)
            pts -= v
            sprints += 1
        results.append(sprints)
    results.sort()
    p50 = results[int(0.50 * n)]
    p85 = results[int(0.85 * n)]
    return p50, p85

# Сценарій 1: весь перший реліз = 25 SP
p50_s1, p85_s1 = simulate(25)  # → 4, 4
end_s1 = date(2026, 10, 30)
d50_s1 = end_s1 + timedelta(days=(p50_s1 - 1) * 14)  # → 2026-12-11
d85_s1 = end_s1 + timedelta(days=(p85_s1 - 1) * 14)  # → 2026-12-11

# Сценарій 2: залишок після двох спринтів = 11 SP (25 − 14 закритих)
p50_s2, p85_s2 = simulate(11)  # → 2, 2
end_s2 = date(2026, 11, 13)
d50_s2 = end_s2 + timedelta(days=p50_s2 * 14)  # → 2026-12-11
d85_s2 = end_s2 + timedelta(days=p85_s2 * 14)  # → 2026-12-11
```

## 3. Дві дати першого релізу

| Сценарій | Points | P50, спринтів | P85, спринтів | P50, дата | P85, дата |
| --- | :-: | :-: | :-: | :-: | :-: |
| Весь перший реліз | 25 | 4 | 4 | 2026-12-11 | 2026-12-11 |
| Залишок після моїх спринтів | 11 | 2 | 2 | 2026-12-11 | 2026-12-11 |

Обидва сценарії збіглися до однієї дати: 2026-12-11. Це не дивно: спринт 2 закінчується 2026-11-13, а два спринти по 14 днів від кінця спринта 2 дають рівно ту саму дату, що й чотири спринти від кінця спринта 1.

Яку дату я називаю замовнику вголос і чому саме її: я називаю **2026-12-11** як P85-прогноз — з імовірністю 85% перший реліз буде готовий до цієї дати. Обирається саме P85, а не P50, бо це консервативна оцінка: половина симуляцій завершується раніше, а 85% дає замовнику розумний запас без надмірного перестрахування.

## 4. Прогноз проти критичного шляху з ЛР7

Чому дати різні: критичний шлях рахує роботу без збоїв за плановими тривалостями завдань WBS; прогноз Monte Carlo рахує фактичну velocity (6–8 SP/спринт) разом із реальними затримками — зокрема перенесенням S-04 між спринтами. Прогноз дає ранішу дату, бо в ньому є ймовірнісний компонент: два спринти по 14 днів від зараз виходять компактніше, ніж розгорнутий критичний шлях із усіма буферами. Ближчим до правди вважаю прогноз P85, бо він враховує фактичні дані, а не лише план.

Що я з цим роблю: дата 2026-12-11 збігається зі строком варіанта — це вже ризик нульового буфера, тому пропоную скоротити обсяг першого релізу: перенести S-11 (5 SP, «Адмін: статистика») у REL-2 і звільнити 5 SP запасу.

## 5. Чого вартий прогноз на моїх даних

Три прогони на навчальних даних курсу `lr09_reference_velocity.csv`, обсяг фіксований умовою, 220 points. Четвертий рядок — мій власний сценарій залишку для порівняння.

| Джерело velocity | Спринтів в історії | P50 | P85 | Ширина інтервалу |
| --- | :-: | :-: | :-: | :-: |
| Навчальні дані, усі спринти | 12 | 12 | 14 | 2 |
| Навчальні дані, спринти 1 і 2 | 2 | 12 | 12 | 0 |
| Навчальні дані, спринти 5 і 6 | 2 | 15 | 18 | 3 |
| Мої спринти | 2 | 2 | 2 | 0 |

Що показує це порівняння: коли в історії лише два спринти, симулятор тягне velocity з дуже малого пулу — або 21/17, або 6/8 — і розкид виходить вузьким або нульовим не тому, що прогноз точний, а тому, що вхідних даних замало для варіативності. На 12 спринтах навчальних даних виходить ширина інтервалу 2 спринти, що чесніше відображає реальну невизначеність. Нульовий інтервал у двох рядках таблиці — це не точність, а брак інформації: одна аномалія (блокер, хвороба, складна задача) у наступному спринті повністю змінить прогноз.
